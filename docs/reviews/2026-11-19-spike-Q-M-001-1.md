# Spike Q-M-001-1: `#src/*` imports aliases across the toolchain

Date: 2026-11-19. Status: findings of a timeboxed spike (ADR-0040). Ephemeral.

**Question.** R-019 rules that in-package code shares through package.json
`imports` aliases (`#src/*`), with toolchain support unverified. Does this
repo's toolchain support them end to end?

**Method.** On branch `spike/Q-M-001-1` (spike commit `d8602b3`, not for
landing), `@hexagram/core` gained `"imports": { "#src/*": "./src/*" }`;
`src/getters.ts`, `src/random-casting.ts` (both build entries; one imports
`#src/index.js`, another entry) and three tests were switched from `./` and
`../src/` to `#src/...js`. Then, run one after another: per-package and root
`type:check`, `build`, `test --force`, `lint:check`, `format:check`, and tsx runs.

**Versions.** Node 24.14.1, pnpm 10.33.4, TypeScript 6.0.3, tsdown 0.22.0
(rolldown 1.0.0, rolldown-plugin-dts 0.25.0), vitest 4.1.6, tsx 4.21.0,
oxlint 1.64.0, eslint 10.3.0.

## Verdict per tool

| Tool | Verdict |
| --- | --- |
| `tsc --noEmit` | Works with today's `tsconfig.base.json` (`module: preserve`, `moduleResolution: bundler`); no `paths`, no `customConditions`. `--traceResolution` shows `#src/types.js` resolved to `src/types.ts`. Root `pnpm type:check`: 25/25. |
| tsdown build | Works. Aliases are resolved at build time. No `#src` appears in any `dist/*.mjs` or `*.d.mts`, and core's `dist/` is **byte-identical** (sha1 of every file) to the build without the alias. Root `pnpm build`: 13/13. |
| vitest | Works. Core tests that import `#src/...` pass (88 + 6 in the slow file). Root `pnpm test --force`: 25/25. |
| tsx | Works. Inside core, `tsx -e "import('#src/getters.js')"` resolves. From `apps/cli`, `tsx --conditions=source` loads core's `src/getters.ts` (and its `#src` imports); plain `tsx` loads `dist/`. `printf … \| pnpm hexagram-random -- --plain` completes a reading. |
| oxlint / eslint | Works with one fix: `jsonc/sort-keys` (eslint) requires `imports` **before** `exports` in package.json. No import-resolution rule complains. oxlint reports the same 8 warnings with or without the spike. |
| Cross-package / `source` | Works. Node resolves `#` specifiers against the importing file's nearest package.json, so a consumer loading core via `source` (vitest, tsx with `--conditions=source`) or via `dist` (tsc types, node runtime) never needs core's alias. All consumer packages' tests and type checks pass. |

**Minimal config required.** Only the `imports` field in the package's
package.json, placed before `exports`. No tsconfig, tsdown, vitest or eslint
change.

## Gotchas observed

1. **The `.js` extension is required for tsc.** `#src/models/trigrams`
   (no extension) fails tsc with TS2307 even under `bundler` resolution,
   because TypeScript does not probe extensions on `imports` patterns. vitest
   and tsx accept the extensionless form, so the tools disagree. Specifiers
   must be written `#src/….js`, and tsc maps `.js` to `.ts`.
2. **No lint rule enforces R-019.** eslint accepted a file that mixed `./`
   and `#src/` imports in either order. The import sorter puts `#src` in its
   own group after external packages. Nothing flags a leftover `../` chain.
3. **The `imports` map is published.** `files: ["dist"]` excludes `src/`, so
   the published package.json carries an `imports` entry that points nowhere.
   This is harmless, since `dist` never references `#src`.
4. **No conditions are needed on the `imports` entry.** A plain string target
   works for every tool, so ordering of conditions is not an issue.
5. `#/*` (a bare `#/` prefix) also resolves under Node 24.14.1 (checked in a
   scratch package). `#src/*` needs no special Node version.

## Pre-existing, unrelated to `imports`

- `CLAUDE.md` says the CLIs run through tsx with the `source` condition. They
  do not: the root scripts pass no `--conditions`, so on a fresh worktree
  `pnpm hexagram-random` fails until `pnpm build` has made `dist/`
  (ERR_MODULE_NOT_FOUND on `casting-ui/dist/index.mjs`).
- `tsx --conditions=source apps/cli/src/random.ts --plain` with piped stdin
  ends with `ExitPromptError`, with or without the spike change.
