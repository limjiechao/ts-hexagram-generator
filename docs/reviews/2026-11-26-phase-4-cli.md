# Phase 4, the CLI at parity: scope and breakdown into Matters

Date: 2026-11-26. Status: copilot draft for the Phase 4 breakdown (ADR-0042,
"Roles"; `MATTERS.md`, "Phases 3–6 are broken into Matters by the owner, with
the copilot"), revised after the challenger; ephemeral. It binds nothing
until the owner rules on it.

**What is being decided.** What "the CLI at parity with today's app, on the
new core" (ADR-0042, "Build order and budgets", step 3) covers, and what it
leaves to Phases 5 and 6; how today's `apps/cli` is retired; how the phase
splits into serial Matters within the owner's budget of 12 Matters, 8 weeks,
60 owner touches per Matter and 1,500 lines per brief (`MATTERS.md`, phase
table); each Matter's draft entry; and the Tier-A questions and spec holes
visible now, before any tester's audit (section 4). Parity means "matches
the ratified manual", `docs/manual/cli.md` (R-008, R-353); byte fixtures
stay the standard for exact output.

**Facts checked in the tree (2026-11-26, `matters` at be8989a).**

- **Stubs.** `grep notImplemented overhaul/*/src` finds 7 calls, all in
  `application`: use cases 4, 5, 6, 7, 9, and `exportJournal` and
  `mergeJournal` (10).
- **`composeCli` already takes all four ports** and returns 11 functions. It
  is called 22 times in 6 approved test files. Stub Scripture Catalogues
  appear in 7 test files across `application` and `cli-adapter`. Widening the
  return type breaks no call; adding a member to a port breaks every stub of
  it (R-306).
- **Packages.** `overhaul/` holds `oracle`, `remainder-group-policy`,
  `consultation-journal`, `scripture-catalogue`, `application` and
  `cli-adapter`. Layout C (R-025; `docs/reviews/2026-11-19-m-001-package-layout.md`)
  names the later ones: `store-markdown`, `catalogue-bundled`,
  `node-effects`, `presentation` (pure, R-105) and `legacy-import`. None
  exists yet.
- **Boundary table.** `cli-adapter`'s production code may import only
  `application`; its tests may also import `consultation-journal` and
  `scripture-catalogue` (R-135, R-281). Any `@hexagram/*` import outside the
  table is refused. `drift:prove` holds plants that depend on today's arrows,
  among them `b7-imports-catalogue.ts`, `b7-dynamic-import-oracle.ts` and
  `b8-test-imports-oracle.test.ts` (`scripts/drift/fixtures/signal-3/expected.ts`).
  **`drift:prove` is not in `check:all`**, so only an Acceptance that names it
  runs it.
- **The ports.** The Store's `keep` takes only a `Consultation`, and keeping
  an Id it holds does nothing (`consultation-store.ts`). So the Markdown body
  (ADR-0030), re-rendering bodies, moving imported originals and locating
  the Journal folder all fall outside the port. The Catalogue has
  `passageTexts`, `hexagramNames` and `editions`: **no Received Sequence
  Number and no Trigram names**, though the manual shows both (R-341).
  `Edition` has **no field for a conversion label** (R-344).
- **The codec.** ADR-0030 requires "one shared codec" for version-2 records.
  None exists.
- **Scripture data.** The legacy models hold the 經 (Traditional,
  Simplified, Legge, Wilhelm–Baynes) with the 彖傳, 大象 and 小象. A grep of
  `domain`, `cli` and `apps` finds **no 用九 / 用六, no 文言, no 焦氏易林**. The
  default Readout shows 用九 / 用六 (the All-Moving Statement) whenever all six
  lines of 乾 or 坤 move (manual section 4 and section 5, tab 3), so **parity
  fails at the default Reading Preference** without it.
- **An ADR conflict.** ADR-0030 says the body is "rendered by Presentation's
  Markdown renderer", and `CONTEXT.md` makes Presentation "Readouts in every
  medium". ADR-0022 holds that the Markdown body is a monospace rendering,
  medium-bound, on the CLI side.
- **Today's app.** About 31,000 lines across `cli/*`, `apps/cli` and the
  legacy file and view packages, tests included (12,600 source and 16,900
  tests in `cli/*` alone). The Viewer's packages (`casting-ui`, `viewer-core`,
  `readout`, `text-grid`) are about 7,800 lines of source and 10,000 of tests.
  Byte-fixed today: plain output, Ink sections
  (`cli/casting-ui/tests/fixtures/ink-sections-*.json`), Markdown bodies and
  whole files (`cli/text-grid/tests/fixtures/md-file-*.md`).
- **Folding owed.** R-332 amends ADR-0010 but is not folded; ADR-0010 carries
  a separate 32-row amendment; ADR-0011 carries ADR-0043 as a note. ADR-0042
  folds amended ADRs into one text before code depends on them.
- **Acceptance mechanics.** `vitest run a.test.ts missing.test.ts` exits 0
  when at least one named file exists (checked in `cli-adapter`). A child
  process with piped stdout is never a TTY.
- **The manual is 512 lines**, a third of the brief cap.

## 1. Scope of the CLI phase

PH4-1 (A) puts every driven adapter the CLI needs, the seven remaining
use-case stubs, and the six commands as the manual describes them in
Phase 4:

| In Phase 4 (A) | Left to Phase 5 (REST) | Left to Phase 6 (PWA) |
| --- | --- | --- |
| `node-effects`: Clock, Random Source (`node:crypto`) | the REST engine, Casting URLs, HAL, B14 (ADR-0038) | `store-indexeddb`, WebCrypto, the REST-client Catalogue |
| `catalogue-bundled`, Edition and Witness records (ADR-0028) | serving the Catalogue over HTTP | the PWA's trust function, B13 (R-031, R-151) |
| `store-markdown` and the codec (ADR-0030) | `docs/manual/rest.md` | the Journal bundle in the browser (R-348) |
| use cases 4–7, 9, 10; `presentation` (R-105) | | Typst in the browser (R-347) |
| the six commands (manual sections 2, 6, 7); the cutover | | |

用九 / 用六 is a phase-wide data decision (PH4-17); 文言 and the Yilin are
PH4-18's.

**Retirement.** The new Store reads only version 2 and the legacy history
only version 1, so a Journal written by both is half Unreadable in each, and
the bins cannot be swapped one at a time. PH4-2 (A) builds beside the legacy
app, with no root scripts for the new commands until the cutover in M-021.

## 2. Proposed Matters, in serial order

The entries follow PH4-3 (A). Each Matter keeps the walking skeleton running
and extends it, through `composeCli` and, from M-010, through each command's
in-process entry point (PH4-8). Sizes include acceptance material and Phase
2's 1.5 to 3 times overrun.

**Tier-A drafts.** M-010 (the entry point, the usage line), M-011 (data,
Edition records, the wider Catalogue port), M-012 (the codec, its Unreadable
reasons, the frontmatter fixture, `store-markdown`'s public surface), M-013
(`presentation`'s surface, the plain, Ink-section, body and whole-file
fixtures), M-015 (the Deletion Record file, the bundle) and M-016 (the Typst
fixtures, the Typst dependency) draft files for ratification.

**`composeCli`.** M-011, M-012, M-015 and M-016 widen its return type, as
digest lines that break no call. **M-011 widens the Catalogue port**, which
breaks the stub Catalogues in approved tests; R-306's mechanical change by a
fresh tester is planned into its first slice. No Matter adds a port.

**Boundary arrows (R-314).** M-010, M-011, M-012, M-013, M-015 and M-016
change arrows. Each lists its B9 twin and any plant it retires, and its
Acceptance runs `pnpm drift:prove`.

**Acceptance.** Each command starts with `test -f` for every test file it
names, because `vitest run` passes if any one named file exists. Paths are
from the repository root for `test -f` and from the package for `vitest`.
Names are drafts; the tester fixes them in the approved list.

## 3. What Phase 4 does not need to ask

Testers should cite these, not ask:

- The terminal table, refusal line and exit codes (manual sections 2, 6.1;
  R-332, R-350, R-351). An Unreadable file is never an error (R-350).
- Browse filters by case-insensitive substring (manual 6.7). Unreadable means
  failing to load as version 2 or failing replay (ADR-0030), and every
  version-1 file is one (manual section 2). Ctrl+D on one is refused (R-336).
- The Store never parses a filename and never writes on read (ADR-0030);
  keeping an Id it holds does nothing (the port).
- Merging leaves out a Cast Consultation that does not replay and goes on
  (R-350); the caller replays first (`mergeJournal`'s comment).
- Import keeps each file as Cast if its Casting replays, otherwise as
  Recorded, so a file holding only a Transformation is Recorded whatever its
  origin; importing twice keeps twice (manual 6.7, R-334).
- Line 6 can be retracted only while incomplete: the eighteenth Round keeps
  the Consultation at once (manual section 4 and 6.5).
- No write overwrites a file (manual section 9; ADR-0030), so `--export` and
  `--export-journal` refuse an existing path, one line, exit 1 (R-350).
- The Reading Preference options go on every command that shows a Readout or
  exports, maintenance runs included (R-340; manual section 7).
- The Applicable Passages' order and Commentaries (R-283, R-284, R-326); 文言
  is never split by line (R-345); a Translation lacking a passage shows
  nothing (`CONTEXT.md`).

## 5. Risks to the budget

**Verdict: 12 Matters fit only if the Viewer split is absorbed (PH4-3) and
the work runs near the fast end; 8 weeks is at risk at the slow end. Owner
touches on Tier-A drafts and the 用九 / 用六 text are the binding limits.**

- **Weeks.** 12 Matters at 2 to 4 working days each is 5 to 10 weeks, so the
  upper half of the range overruns the budget. Phase 3 ran far faster, but
  it implemented ratified signatures; Phase 4 writes about 18,000 lines
  against Phase 3's 3,300, porting from about 31,000. An Ink flake hunt like
  May 2026's nine rounds would take the margin. The clerk's estimate should
  be checked after M-013.
- **Touches.** Phase 3 spent 37 over five Matters, its holes surfacing at the
  tester's audits. Estimate 25 to 45 each for M-011, M-012, M-013, M-015 and
  M-017, and 15 to 30 for the rest: about 330. Ruling PH4-1 to PH4-29 with the
  breakdown keeps them out of the audits.
- **Caps.** M-013, M-015 and M-017 are the likeliest to reach 60 touches or
  1,500 brief lines. Each brief cites only its manual sections and names
  legacy files, not packages.
- **Fixtures.** Hand-deriving fixtures at 120 columns with CJK widths is
  slow; a wrong one found late reopens a ratified file.
- **Data.** PH4-17 blocks M-011 on the owner's labour. A 13th Matter for any
  text is an overrun.
- **Silent misses.** Every Acceptance checks its files exist and counts what
  is enumerable: Citations, Unreadable reasons, strip states, terminal
  columns.
- **The cutover.** The owner's migration of the real Journal is outside any
  Matter, and only the owner can check it.
