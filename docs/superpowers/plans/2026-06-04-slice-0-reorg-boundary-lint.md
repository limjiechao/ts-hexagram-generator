# Slice 0: Directory Reorg + Boundary Lint — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Move every workspace package from `packages/*` + `apps/*` into `domain/*` + `cli/*` buckets with zero logic change, and add a dependency-cruiser boundary lint that fails any future `domain/* → cli/*` import.

**Architecture:** Two top-level buckets express the architectural intent the later slices depend on: `domain/*` holds reusable, UI-free domain knowledge (a hypothetical Next.js app can consume it without touching any CLI package); `cli/*` holds everything terminal-specific. The move is pure `git mv` plus a handful of glob/script/ignore-pattern edits — `workspace:*` deps are name-based and per-package configs use depth-stable `../../` relative paths, so both survive the move untouched. The new boundary lint is a drift guard: today there are zero `domain → cli` edges, so it passes green immediately.

**Tech Stack:** pnpm workspaces, Turborepo, TypeScript, tsdown, dependency-cruiser

## Task 6 — Add the dependency-cruiser boundary lint (config + tooling)

**Files:**
- Create: `dependency-cruiser.config.cjs` (repo root)
- Modify: `package.json` (root) — add `boundaries:check` script + devDependency

dependency-cruiser is chosen over eslint-plugin-boundaries because it operates on the resolved module graph across package boundaries (it follows `@hexagram/*` workspace imports), runs as a single root command (no per-package eslint wiring), and produces a self-contained config the reviewer can read in one pass. The rule tags modules `domain` (path under `domain/`) and `cli` (path under `cli/`) and forbids any `domain → cli` edge.

`.cjs` extension: the root `package.json` is `"type": "module"`, and dependency-cruiser's `--config` loader expects CommonJS for a `module.exports` config — `.cjs` forces CJS regardless of the package type.

- [ ] Install dependency-cruiser as a root dev dependency (use `-w` to write to the workspace root):
  ```bash
  cd /home/user/ts-hexagram-generator && pnpm add -Dw dependency-cruiser
  ```
  EXPECTED: dependency-cruiser added under root `devDependencies`; lockfile updated.
- [ ] Create `/home/user/ts-hexagram-generator/dependency-cruiser.config.cjs` with EXACTLY this content:
  ```js
  // Architectural boundary guard: no domain/* package may import a cli/*
  // package. domain/* is reusable, UI-free knowledge (consumable by a
  // hypothetical Next.js app); cli/* is terminal-specific. The dependency
  // arrow must always point cli -> domain, never the reverse.
  //
  // Today there are ZERO domain -> cli edges (core depends on nothing;
  // consultation-file depends on core only), so this rule passes green on
  // introduction. It is a DRIFT GUARD that fails the build the moment a
  // future change inverts the arrow — not a detector of a current leak.
  /** @type {import('dependency-cruiser').IConfiguration} */
  module.exports = {
    forbidden: [
      {
        name: 'no-domain-to-cli',
        comment:
          'A domain/* package imported a cli/* package. domain stays UI-free and ' +
          'reusable; dependencies must point cli -> domain, never domain -> cli.',
        severity: 'error',
        from: { path: '^domain/' },
        to: { path: '^cli/' },
      },
    ],
    options: {
      doNotFollow: { path: '(^|/)node_modules/' },
      exclude: {
        path: '(^|/)(node_modules|dist|tests|scripts)/',
      },
      tsConfig: { fileName: 'tsconfig.base.json' },
      enhancedResolveOptions: {
        // Resolve @hexagram/* workspace imports via the `source` export
        // condition so the cruiser follows ./src/*.ts (no build needed),
        // matching how tsx/vitest resolve the workspace.
        conditionNames: ['source', 'import', 'require', 'node', 'default'],
        exportsFields: ['exports'],
      },
    },
  }
  ```
- [ ] Add the boundary script to root `package.json`. Insert this line into `scripts` immediately after the `"build": "turbo run build",` line:

## Risks / honest caveats

1. **The boundary lint detects nothing today — it is a drift guard, not a leak detector.** core depends on nothing; consultation-file depends only on core. There are zero `domain → cli` edges, so the rule passes green the instant it is added. Its value is failing the build when a *future* slice accidentally inverts the arrow. State this plainly in review so no one mistakes the green pass for "we found and fixed leaks."
2. **dependency-cruiser `source`-condition resolution.** The config resolves `@hexagram/*` via the `source` export condition to follow `./src/*.ts` without a build. If a future package omits the `source` condition, the cruiser would fall back to `import` (`./dist/*.mjs`), which requires a prior `pnpm build`. All current packages declare `source`, so this is fine now; flagged for later slices that add packages.
3. **Lockfile churn.** `pnpm install` rewrites importer keys and `link:` versions in `pnpm-lock.yaml`. This is expected and committed in Task 3; reviewers should diff it for *paths only* (no version changes), confirming the graph is otherwise identical.
4. **Non-load-bearing prose references remain.** Source comments (`apps/cli/src/manual.ts`, `cli/casting-ui/src/manual-validation.ts`), `AGENTS.md`, `CONTEXT.md`, and ADR-0002/0003 still say `packages/`/`apps/`. They do not affect build/test/lint/type-check and are deliberately out of scope for this structure-only slice; a later docs slice updates them. Flagged so the worker does not scope-creep into doc edits.
5. **`.cjs` config under an ESM package.** The root is `"type": "module"`; dependency-cruiser's config must be CommonJS. The `.cjs` extension forces this — do not rename it to `.js`.
